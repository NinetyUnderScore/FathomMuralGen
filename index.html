Frequently Asked Questions

Can you add [this feature]

Idk probably, send a message or ping _90_ in the thread for this tool on the Fathom Discord server.

What font is used?

All murals use the Legacy font due to being significantly larger than the other fonts meaning only 80 characters are needed to fill the page.

The generator always opens its output string with <font face='Legacy'> to ensure this font is applied. If a nested color tag has to re-declare the face after a close, it will use <font face='Legacy' color='…'> automatically.

How the character limit works

Papers in Fathom have a hard limit of 400 characters of rich text. Every mural string must fit within this budget. The breakdown is:

<font face='Legacy'> opening = 19 chars
@ × 80 tiles = 80 chars
A nested color tag (<font color='#xyz'>) = 19 chars
A color change at the nesting limit (</font><font color='#xyz'>) = 26 chars
First color (merged into the opening tag as an attribute) = 13 chars

With 80 tiles and the opening tag already consuming 99 characters, a full page leaves room for approximately 11–14 color changes depending on how deeply you are allowed to nest.

Tag nesting limit

Color tags do not have to be closed before the next one starts. A color tag opened inside another simply takes over, and when it closes the previous color comes back. What actually matters is how many tags can be open at the same time.

The Nesting limit slider (0–8) lets you pick the deepest stack your mural is allowed to use. At 0 you must close a tag before opening another (every change costs 26 chars). At 1 you may stack two tags, which makes every change after the first cost only 19 chars. Each extra level gives you one more cheap change.

In the Note Painter the current depth is printed in the corner of every tile, so you can build something manually and immediately see whether it fits the limit you selected.

Overlapping papers (5×6 mode)

Papers can be placed so that they overlap, which means each paper only needs to use its top‑left 5×6 corner. The importer writes five @ per row followed by a newline, and leaves the bottom four rows untouched.

Each paper then carries 30 tiles instead of 80. That costs you roughly 2.7× more papers for the same picture, but the string has ~45 extra characters of headroom, which buys several additional color changes per paper — so small details survive instead of being averaged away.

How optimizations work

First-tile color merge

If only one color tag appears on the entire paper and it's on tile 1, it's merged directly into the opening <font face='Legacy'> as a color attribute instead of being a separate tag.

No space between attributes

Roblox's rich text parser doesn't require a space between consecutive tag attributes, so face='Legacy'color='#fff' is valid. The generator never adds that space, saving 1 character per combined tag.

Nested instead of closed

As long as the nesting limit allows it, a new color tag is opened inside the previous one instead of closing first. That is 19 characters instead of 26 — a 7 character saving on almost every color change.

Minimal font re-declaration

After a </font> closes a color tag, the Legacy face is only re-declared in the next opening tag if the stack no longer has a face tag active. If Legacy is already set by a parent tag still open, the new tag is just <font color='…'>.

No-op close drops

A </font> on a tile that has nothing to close is dropped from the output as it would waste 7 characters and do nothing visually.

Redundant reopen elimination (⚠)

If a tile closes a color and the very next open tag would reopen the exact same color, the entire close+reopen pair is eliminated. The tile is flagged with ⚠ in the editor. This saves 26 characters at the cost of the one tile's color being "inherited" from the parent.

Unclosed trailing tag

The outermost <font face='Legacy'> (as well as the last color tag) is never closed at the end of the string. Roblox does not require tags to be closed and leaving it open saves 7 characters.

Stroke

Enabling stroke in Settings adds <stroke thickness="5"> right after the opening font tag. It stays open for the whole page, so it uses 22 characters and occupies one open-tag slot, leaving one less level of color nesting.

Nested islands (resuming the outer color)

When a small patch of one color sits inside a larger area of another, the importer doesn't need three separate tags. It opens the patch's tag inside the outer one and closes it again, and the outer color simply resumes:

<font color='#fff'>@<font color='#f00'>@</font>@

An island costs 26 chars (19 to open + 7 to close). Re-declaring the outer color afterwards would cost another 19 or 26, so every island saves at least 19 chars compared to a plain color change and the savings are spent on extra detail elsewhere. Islands need one spare level of nesting, so they are unavailable at a nesting limit of 0. Up to 3 islands are considered per color run.

Image importer: how color regions are chosen

The image importer solves an optimization problem to decide where to place color boundaries. The solver tracks, for every tile position, every possible "characters spent so far" amount and every possible nesting depth, keeping only the best color error reachable for each combination. From that it picks the cheapest‑error path that still fits inside the character budget and the nesting limit.
